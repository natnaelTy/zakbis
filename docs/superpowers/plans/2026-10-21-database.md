# Database (Supabase) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace `supabase/migrations/0001_buy_me.sql` with a schema that enforces every approved product rule, prove it with SQL tests on a throwaway local Postgres, then apply it to the user's fresh Supabase project.

**Architecture:**
- One migration file holds the tables, row-level security, security-definer functions for every status change and reveal, the views and the storage buckets and policies.
- Tests are plain SQL files. Each runs inside a transaction that rolls back, with `ASSERT`s, against a local Postgres 16. Stand-ins mimic Supabase's `auth` and `storage` schemas.

**Tech Stack:** PostgreSQL 16 (`/usr/lib/postgresql/16/bin`), Supabase (Auth, Storage, RLS), `psql`.

**Spec:** `docs/superpowers/specs/2026-10-21-database-design.md`

## Global Constraints

- **Dates:** "today" is always `addis_today()` = `(now() at time zone 'Africa/Addis_Ababa')::date`.
- **Money:** whole birr.
  - `item_etb = round(unit_price * quantity * fx_rate)`
  - `fee_etb = round(reward_etb * 9 / 100.0)` (numeric math, never integer division)
  - `total_etb = item_etb + reward_etb`
  - `payout_etb = total_etb - fee_etb`
  - These are generated columns, so the browser never sets them.
- **Statuses:** `open`, `declined`, `awaiting_payment`, `paid`, `purchased`, `landed`, `delivered`, `paid_out`, `cancelled`. Status changes only through functions; there's no direct `update` on `requests`.
- **Phone:** read only from `auth.users.phone` where `phone_confirmed_at is not null`.
  - **Landed** requires the traveler's phone to start with `251`.
  - **An escrow proof** requires the receiver's phone to be confirmed (any +251 number, since receivers are in Addis).
- **Reveal:** never Telegram or email.
  - The traveler sees the receiver's phone from `purchased`.
  - The receiver sees the traveler's phone from `landed`.
  - A revealed number stays revealed after `cancelled`.
- **Anon (no login):**
  - **Can read:** listed trips (`shop_by >= today`), live open requests (`kind = 'open'`, `status = 'open'`, `needed_by >= today`), the public profile columns (`id`, `first_name`, `photo_blur_path`, `verified`), the stats views and reviews.
  - **Can't:** write anything, or call any function successfully.
- **Storage:** `screenshots` and `photos-blur` are public. `photos` and `proofs` are private. Uploads go under `<auth.uid()>/…`.
- **Applying:** never drop the user's tables. Applying to Supabase happens only after the user confirms that the target is the new, empty project.
- **Commits:** only if the user asks.

## Review Focus

1. **Two accepts racing on the same open request:** only one offer becomes accepted. → Task 3 test "accept twice fails".
2. **An offer after `needed_by`, or from a trip past `shop_by`,** is refused. → Task 3 tests.
3. **Self-dealing:** a receiver offering on their own request, or a traveler requesting on their own trip, is refused. → Task 2 and Task 3 tests.
4. **A request in a currency with no `fx_rates` row** fails with a clear error, never a null rate. → Task 2 test.
5. **Anon calling `advance_request`, `make_offer` or `counterpart_phone`** gets an error or null, never data. → Task 2 test.

### Task 1: Local test harness

**Files:**
- Create: `supabase/tests/stubs.sql`, `supabase/tests/run.sh`
- Modify: `.gitignore` (add `supabase/tests/.pg/`)

**Interfaces:**
- Produces:
  - `sh supabase/tests/run.sh` does five things:
    - starts a throwaway cluster in `supabase/tests/.pg` on port 54329 over TCP (the Unix socket path is too long here);
    - applies `stubs.sql`, then `supabase/migrations/0001_buy_me.sql`;
    - runs every `supabase/tests/*_test.sql` with `ON_ERROR_STOP=1`;
    - prints `PASS <file>` or `FAIL <file>` for each, and exits non-zero on any failure;
    - stops the cluster.
  - `stubs.sql` provides:
    - the roles `anon`, `authenticated` and `service_role`;
    - `auth.users(id uuid pk, email text, phone text, phone_confirmed_at timestamptz)`;
    - `auth.uid()`, which reads `current_setting('request.jwt.claim.sub', true)`;
    - `storage.buckets(id, name, public)`, `storage.objects(id, bucket_id, name, owner)` with RLS enabled, and `storage.foldername(text) returns text[]`;
    - grants: usage on `public`, `auth` and `storage` to `anon` and `authenticated`, and default privileges on public tables and functions to both.
  - **Tests become a user by** running `set local role authenticated` (or `anon`) and `set local request.jwt.claim.sub = '<uuid>'`.

  - `trips`
  - `requests`:
    - columns: `kind`, `trip_id`, `countries country_code[]`, `needed_by`, `item_url`, `screenshot_path`, `quantity` (1–10), `unit_price`, `currency`, `fx_rate`, `reward_etb`, and the generated `item_etb`, `fee_etb`, `total_etb`, `payout_etb`;
    - `check (item_url is not null or screenshot_path is not null)`;
    - the per-kind checks from the spec.
  - `handover_codes`
  - `payments(kind escrow|payout|refund)`
- **Produces these functions** (all `security definer`, `search_path = public`):
  - `addis_today() returns date`
  - `is_admin() returns boolean`
  - `phone_of(uid uuid) returns text`: the confirmed phone, or null
  - `advance_request(p_id uuid, p_to request_status, p_code text default null, p_receipt text default null) returns void`
  - `counterpart_phone(p_request uuid) returns text`
- **Produces these triggers:**
  - **`requests` before insert:**
    - forces `receiver_id = auth.uid()`, `status = 'open'` and `fx_rate` from `fx_rates`, raising `'no fx rate for <cur>'` when the currency has none;
    - for `kind = trip`, sets `traveler_id` from the trip and refuses if the receiver is that trip's traveler;
    - for `kind = open`, refuses a `needed_by` outside `addis_today() + 3 .. + 60` and forces `reward_etb = null`.
  - **`requests` after insert:** creates the handover code.
  - **`payments` before insert:** for an escrow, forces `amount_etb = total_etb` and `status = 'pending'`.

### Task 3: Open requests and offers

**Files:**
- Modify: `supabase/migrations/0001_buy_me.sql`
- Test: `supabase/tests/open_flow_test.sql`

**Interfaces:**
- **Consumes:** Task 2's tables and `advance_request`.
- **Produces:**
  - the table `offers(id, request_id, traveler_id, trip_id, reward_etb ≥ 1, status pending|accepted|rejected|withdrawn, created_at)`, with a unique index on `(request_id, traveler_id) where status in ('pending', 'accepted')`;
  - `make_offer(p_request uuid, p_trip uuid, p_reward int) returns uuid`: the caller must own `p_trip`, can't be the receiver, the request must be `open` with `kind = open`, and the trip must match (origin ∈ countries, arrival ≤ needed_by, shop_by ≥ today, needed_by ≥ today);
  - `accept_offer(p_offer uuid) returns void`: receiver only; locks the request; sets `traveler_id`, `trip_id`, `reward_etb` and status `awaiting_payment`; marks the other pending offers `rejected`;
  - `reject_offer(p_offer uuid)`: receiver only;
  - `withdraw_offer(p_offer uuid)`: the offering traveler, while pending.
  - **Offer visibility:** the request's receiver and the offering traveler can read offers; no one else can.

- [ ] **Step 1: Write `open_flow_test.sql`**, with these assertions:
  - **Posting:** R posts an open request (countries `{AE,US}`, `needed_by` = today + 10, no reward). Its `reward_etb` is null, and anon can read it.
  - **A matching offer:** T (AE trip landing today + 5) offers 600, which succeeds.
  - **Offers that are refused:**

  - **After `needed_by` has passed:** an open request whose `needed_by` is in the past (set as superuser) can't be read by anon and refuses `make_offer`.
  - **The rest of the path:** after accepting, the request follows Task 2's path. Assert only that T can move it to `purchased` after `paid`.
