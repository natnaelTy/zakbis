# Reviews Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Both sides review each other after a paid order ends (stars, optional tags, an optional comment, an optional private note), hidden until both have reviewed or 14 days pass. Ratings show from 3 reviews with tag counts. People can report reviews, and low ratings flag travelers and receivers to an admin, who can dismiss, revoke or block.

**Architecture:** One migration, `0012_reviews.sql`, built task by task. Reviews gain tags, a side and visibility columns. Private notes live in their own table that only admins can read. Writes go through `submit_review`. A trigger on `requests` opens the 14-day window when an order is delivered or a refund is decided. Reveals by time and the day-7 reminder ride on `run_deadlines()`. Flags, reports and receiver blocks are tables plus admin functions. The UI adds a review card on the order page, a shared review list (trip page, and receiver reviews for travelers), and an admin Reviews page.

**Tech Stack:** Next.js 16 App Router, React 19, Tailwind/shadcn, Supabase (Postgres 16, RLS).

**Spec:** `docs/superpowers/specs/2026-10-30-reviews-design.md`

## Global Constraints
- **Which orders can be reviewed:** those with `review_open_at` set, which happens when the status becomes `delivered`, or `refund_decided_at` goes from null to set. Only before `review_open_at + 14 days`, and only by the receiver or traveler of that order, about the other.
- **Review content:**
  - rating 1–5 (required);
  - tags: any subset of the side's list;
  - comment: optional, trimmed, empty means null, up to 1,000 characters, `has_contact` → "please remove phone numbers, @handles, emails and links";
  - private note: optional, up to 1,000 characters, not filtered.
- **Tag keys and labels:**
  - about a traveler: `easy_to_reach` (Easy to reach), `on_time` (On time), `polite` (Polite), `as_described` (Item as described);
  - about a receiver: `easy_to_reach`, `on_time`, `polite`, `clear_request` (Clear request).
- **Visible** means `visible_at is not null and hidden_at is null`. `visible_at` is set for both reviews when the second one arrives, or by the deadline job at `review_open_at + 14 days`.
- **"New traveler" / "New receiver"** until 3 visible reviews (`MIN_REVIEWS = 3`); then the average to one decimal, plus tag counts.
- **Report reasons:** `contact` (Contact details), `abusive` (Abusive), `untrue` (Not true). Only the subject can report, once.
- **Flag rule,** per subject and side, over visible reviews: 2 or more of the last 10 at ≤ 2 stars, or 3 or more reviews with an average below 3.5. It needs no open flag, and if there's a dismissed flag, a ≤ 2-star review made visible after `dismissed_at`.
- **Blocking a receiver:**
  - closes their open requests and pending offers, and their `awaiting_payment` orders without a pending screenshot, with a note to each traveler involved;
  - after that, `requests_before_insert`, the receiver's pricing turn (`check_turn` with `'receiver'`) and `submit_payment` refuse with "your account can't make new requests";
  - paid orders carry on.
- **Revoking a traveler** uses the existing `decide_verification(p_user, false, 'Other')`.
- **Notes** go through `notify()`:
  - the window opens: `How was %s? Leave a review for %s.`;
  - the day-7 reminder: `A week left to review %s for %s.`;
  - admins are notified once per new flag or report, through every profile with `is_admin`, using side `receiver` and a null request.
- **Migration** applied by the user inside `begin;`/`commit;`. Never commit `.claude/`, `CLAUDE.md`, `skills-lock.json`, `graphify-out/`, `.env*` or `next-env.d.ts`. Run `graphify update .` after code changes.
- **Tests:** `sh supabase/tests/run.sh`, `node --test lib/*.test.ts`, `npm run lint`, `npm run build`.

## Review Focus
1. **The private note leaking** through any select: the `reviews` table, the views, `reviews_about`, or the order page. Only admins may read `review_notes`. Tested in Task 1.
2. **Reading the other side's review before writing yours**, through a direct `select * from reviews` as the subject or anyone else. Tested in Task 1.
3. **Hidden or not-yet-visible reviews counted** in `traveler_stats`, `receiver_stats` or the tag counts, or shown on the trip page. Tested in Task 1 and Task 3.
4. **A block that misses a path:** a blocked receiver accepting a price, suggesting, paying or posting through the database. Tested in Task 3.
5. **Flag spam:** the same person re-flagged on every reveal after a dismissal without a new low review. Tested in Task 3.

### Task 1: Reviews core

**Files:**
- Create: `supabase/migrations/0012_reviews.sql` (section "Reviews")
- Rewrite: `supabase/tests/reviews_test.sql` (keep its setup style; add helpers through `after_paid_test.sql`'s pattern where useful)

**Interfaces:**
- Produces:
  - **`reviews`:**
    - `text` nullable;
    - new columns: `side text not null check in ('traveler','receiver')` (the side of the *subject*), `tags text[] not null default '{}'`, `visible_at timestamptz`, `hidden_at timestamptz`, `reported_at timestamptz`, `report_reason text`, `report_kept_at timestamptz`.
  - **The `review_notes` table:** `(review_id uuid primary key references reviews on delete cascade, note text not null)`. RLS is on with no policies.
  - **On `requests`:** `review_open_at timestamptz` and `review_reminded boolean not null default false`.
  - **The `requests_review_window` trigger** (before update) sets `review_open_at = now()` when the status changes to `delivered` (from any other status) or `refund_decided_at` goes from null to set. It notifies both sides with the window-open note.
  - **`can_review(p_request, p_author, p_subject)`** replaced with the window rule.
  - **SQL `review_tag_ok(p_side text, p_tags text[]) returns boolean`.**
  - **SQL `submit_review(p_request uuid, p_rating int, p_tags text[] default '{}', p_text text default null, p_private text default null) returns uuid`.** It:
    - locks the request;
    - checks the caller is a party, the window and the inputs;
    - inserts the review and any note;
    - if the other side's review exists, sets `visible_at = now()` on both and calls `check_flags` for both subjects. In this task, `check_flags` is a stub that does nothing; Task 3 fills it in.
  - **Policies:** the "write own review" insert policy is dropped. "reviews public" is replaced by `visible_at is not null and hidden_at is null` or `author_id = auth.uid()` or `is_admin()`.
  - **Views** `traveler_stats` (keeping the columns `traveler_id, rating, review_count, deliveries, verified`) and `receiver_stats` (`receiver_id, rating, review_count`) count only visible reviews, with the side taken from `reviews.side`.
  - **New view `review_tag_counts(subject_id, side, tag, n)`** over visible reviews, granted to anon and authenticated.

### Task 3: Flags, reports, receiver blocks

**Files:**
- Modify: `supabase/migrations/0012_reviews.sql` (section "Keeping reviews clean")
- Test: `supabase/tests/reviews_test.sql`

**Interfaces:**
- Produces:
  - **The `review_flags` table:** `(id, user_id references profiles, side text, created_at, decided_at, decision text check in ('dismiss','revoke','block'))`. RLS is on with no policies.
  - **The `blocked_receivers` table:** `(user_id primary key references profiles, blocked_at, blocked_by)`. RLS is on with no policies.
  - **`is_blocked_receiver(uid uuid) returns boolean`** (internal).
  - **`check_flags(p_user uuid, p_side text)`:** the real body, implementing the flag rule. It inserts a flag and notifies admins: `Reviews to check: %s (%s) has low ratings.`
  - **`notify_admins(p_body text)`** (internal).
  - **`report_review(p_review uuid, p_reason text)`:** the subject only, visible reviews only, once. It sets `reported_at` and `report_reason`, and notifies admins: `A review of %s was reported: %s.`
  - **`decide_report(p_review uuid, p_hide boolean)`:** admin. Hide sets `hidden_at`; keep sets `report_kept_at`.
  - **`resolve_flag(p_flag uuid, p_action text)`:** admin. `dismiss` works for either side. `revoke` is for a traveler flag only and calls `decide_verification(user, false, 'Other')`. `block` is for a receiver flag only: it inserts into `blocked_receivers` and closes unpaid activity per Global Constraints.
  - **`unblock_receiver(p_user uuid)`:** admin.
  - **`reviews_to_check()`:** admin. Returns `(kind text ('flag'|'report'), flag_id, review_id, user_id, side, name, created_at, rating, report_reason, review_text)`, covering open flags and undecided reports.
  - **`reviews_about(p_user uuid, p_side text)`:** admin. Returns the last 20 reviews about that person on that side, including hidden ones, with `rating, tags, text, note, author_name, created_at, hidden_at`.
  - **Replaced with a blocked check added:** `requests_before_insert` (copy 0011's), `check_turn` (copy 0009's), `submit_payment` (copy 0010's).

- [ ] **Step 1: Write the failing tests:**

    - three visible reviews averaging 3.0 → a flag on a fresh subject.
  - **Reports:**

  - **Admin-only and private:**

    - as an admin, `reviews_about` returns the private note;
    - as Hana, `review_notes` is still unreadable.
